# 设计系统 —— Kotae 0.2.3

本文件是界面的**唯一权威规范**。新增功能、改样式、调布局之前先读它；实现与本文件冲突时，以 `src/style.css` 顶部令牌段为最高事实源，并在同一次改动里把本文件改回来。

```text
改 UI 的顺序：查本文件 → 只用既有令牌与原语 → 跑 npm run lint:ui → 浅色/深色各截一张图 → 提交
```

---

## 1 基调（不可协商）

| 维度 | 定调 |
| --- | --- |
| 气质 | 本地工具、高信息密度、低装饰噪音。像一个好用的编辑器，不像营销页 |
| 底色 | 中性冷灰（亮色偏冷白，暗色近黑偏蓝） |
| 强调色 | **只有一种**：靛蓝。第二强调色一律不批 |
| 圆角 | 小圆角、方硬感。不用大圆角卡片、不用胶囊包住整块区域 |
| 阴影 | 只用于「浮起」的元素（弹层、菜单、按钮轻投影），不用于分区 |
| 字体 | 界面用无衬线（Inter / 系统 UI 字体），数据用等宽（monospace）。正文 13px |
| 动效 | 只做「状态切换被看见」：≤ 180ms，缓出，无回弹、无位移表演 |
| 文案 | 全中文，动词开头，一句话说完 |

## 2 令牌三层与铁律

```text
全局物理值  ──►  别名令牌（--accent / --text-2 / --fs-md …）  ──►  组件规则（.btn / .kv-row …）
只在 :root 与主题块里出现        代码只允许引用这一层                组件内不得再写字面量
```

铁律（`npm run lint:ui` 会扫）：

1. **禁止裸色值**：`#hex`、`rgb()`、`hsl()` 只允许出现在 `:root` 与两个暗色块里。
2. **禁止裸字号**：不得写 `font-size: 12px`，只能写 `var(--fs-*)`。
3. **禁止裸圆角**：不得写 `border-radius: 6px`，只能写 `var(--radius-*)`（`50%` 除外）。
4. **禁止裸阴影**：只能写 `var(--shadow-1|2|3|btn)`。
5. 需要新颜色/新字号时：先判断现有令牌能否覆盖；覆盖不了才加，且必须**同时**在
   `:root`、`html[data-theme="dark"]`、`html[data-theme="auto"]`（`prefers-color-scheme: dark`）三处补齐，再登记到本文档。

| 令牌 | 用途 |

| `--speed` | 140ms，所有 `transition` 的默认时长 |

| 动画 | 时长 | 用途 |
| --- | --- | --- |
| `fade-in` | 120ms | 遮罩层淡入 |
| `pop-in` | 90ms / 180ms | 90ms 用于下拉菜单与通知；180ms 用于对话框、命令面板、引导卡片（`translateY(6px) scale(.985)` → 原位） |

### 4.2 栅格与间距

- 基准 4px；允许的间距值：**2 / 4 / 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24 / 26**。
- 组件内间距（`padding` / `gap`）优先 4 / 6 / 8 / 10；区块之间用 12 / 16；对话框内边距 26。
- 分隔一律用 `1px solid var(--border)`；要更明显时用 `--border-strong`，不靠加粗或加阴影。
- 不做「卡片套卡片」；需要分组时用标题 + 1px 分隔线，而不是再加一层边框。

### 4.3 层级（z-index）

| 值 | 用途 |
| --- | --- |
| 1 | 粘性「新增标签页」按钮 |
| 5 | 拖拽分割条 |
| 20 | 顶栏 |
| 40 | 顶栏下拉菜单（环境菜单） |
| 100 | 对话框遮罩 `.backdrop` |
| 200 | 输入补全浮层 `.assist` |
| 250 | 挂在 `body` 上的弹出菜单（右键菜单 `.ctx-menu` / 下拉 `.select-menu`）：共享设置、全局操作这些对话框里也要用，必须压过遮罩 100，但仍要低于确认框 |
| 300 | 应用内确认/输入框 `.prompt-backdrop` |
| 400 | 通知 `.toasts` |

新增浮层先看能否复用上表档位；不得出现 41、99 这类插空值。

## 5 组件原语（不得另起炉灶）

新增界面先在下表找可复用的，找不到再扩展原语，扩展后必须在本表登记。

| 原语 | 类名 | 变体 / 状态 | 约束 |
| --- | --- | --- | --- |
| 按钮 | `.btn` | `primary` / `ghost` / `danger` / `danger-solid` / `small` ；hover / active / disabled | 图标 + 文字间距 6px；禁止两行文案 |
| 图标按钮 | `.icon-btn` | 默认 28 / `mini` 22；hover 有底色 | 必须有 `title` 或 `aria-label` |
| 文字按钮 | `.link-btn` | 强调色文字，hover 出现底色 | 只用于行内轻量动作 |
| 输入框 | `.text-input` / `.search-input` / `.url-input` | default / focus / invalid / disabled | 高度 30px，字号 `--fs-md`；focus 用 `--accent-ring` |
| 变量高亮 | 原生输入框：`.var-host` / `.var-mirror`（`.on` / `.single`）/ `.var-inner` / `.var-token`（`.missing`）/ `.var-input`；代码框：`::highlight(kotae-var)` / `::highlight(kotae-var-missing)` | 有变量 / 无变量 / 未定义 | 两套机制，按控件类型选，不要互换：**原生单行/多行输入框**用镜像层——镜像照抄字体、内边距、边框宽度（画成透明）与滚动偏移，位置尺寸取输入框的盒，两者逐像素重合，此时输入框转成 `.var-input`（文字透明，只留光标与选区），值里没有 `{{}}` 就退出镜像、由输入框自己画字（地址栏、键值表的值列、认证字段用这一套，`src/ui/varTokens.ts`）；**自建代码框**（`.code-editor`）直接给真文本挂 `::highlight()` 区间，没有镜像也没有透明文字。两套都走同一个 `scanVars()` 判定变量与「未定义」，不要再写第二份高亮 |
| 代码输入框 | `.code-input` / `.code-editor`（`[data-empty="true"]`）/ `::highlight(kotae-hl-comment)` `.kotae-hl-str` `.kotae-hl-num` `.kotae-hl-kw` `.kotae-hl-builtin` `.kotae-hl-fn` | 空值（占位提示）/ 有值 / 聚焦 / 超长值退色 | 全应用唯一的代码类多行输入（`src/ui/codeEditor.ts`）：`div` + `contenteditable="plaintext-only"`，浏览器负责光标、选区、输入法、撤销，组件只画外观与着色。请求体、GraphQL 查询与变量、脚本源码、cURL 与导入框都用它，**不要再写原生 `textarea`**（键值表多行值、批量粘贴框、消息框仍用 `textarea`，那几处不是代码）。着色用 CSS Custom Highlight API 给真文本挂区间（组名 `kotae-<kind>`），所以滚动、折行、换主题都自动跟随，**禁止退回镜像层**（镜像要逐像素对齐，字重/字距一变就与光标错位）。配色只复用方法色与状态色：注释 `--text-3`、字符串 `--m-get`、数字 `--m-post`、关键字 `--m-put`、内置对象（`pm`/`console`/`JSON`）`--redirect`、函数调用 `--accent`，不要为语法另开新色；值空或超过 20000 字符就不着色。占位提示画在 `::before`（`content: attr(data-placeholder)`），读写值用组件自带的 `value` / `setSelectionRange` / `caretRect`，e2e 可以直接赋值后派发 `input` |
| 变量浮层 | `.var-tip`（`.on`）/ `.var-tip-head` / `.var-tip-name` / `.var-tip-tag`（`.missing`）/ `.var-tip-value`（`.missing`） | 已定义 / 未定义 | 鼠标移到变量片段上弹出：变量名（等宽、强调色底）+ 来源标签（环境变量 / 集合变量 / 全局变量 / 动态变量 / 未定义）+ 解析值（等宽、`max-height: 168px` 可滚）。`fixed` + `z-index: 210`，优先贴在片段上方、放不下翻到下方、左右钳在视口内；鼠标移开、失焦、滚动、按下鼠标、`mygo:close-popovers` 都收起。**不要退回原生 `title` 提示**（样式不受令牌控制，深色主题下会是白底黑字） |
| 字段容器 | `.field` + `.field-label` + `.field-hint` | 单列 / `form-grid` 双列 / `form-single` 整行 | 提示文字独占整行（`.field-hint{grid-column:1/-1}`） |
| 键值表 | `.kv-row` / `.kv-key` / `.kv-value` / `.kv-check` / `.kv-del` / `.file-btn` / `.kv-secret` | 行 hover 显删除 | 勾选框 14×14；删除按钮默认浮在行尾（值为最后一列时），行尾另有文件控件时用 `:has()` 让它回到文档流，两者永不重叠；`.kv-secret`（锁）默认半透明、hover 变实、开启时强调色，切换只改输入框 `type` |

## 6 图标

- 唯一来源：`src/ui/dom.ts` 的 `icons`（24×24 viewBox，`stroke: currentColor`，`stroke-width: 1.7`，圆角端点）。
- 尺寸只允许 16 / 13 / 12 三档（由 `.ic` 与上下文类控制），不得用 `width: 14px` 这类散值。
- 一个动作一个图标；同类动作复用同一图标（删除永远用 `close/trash`，新增永远用 `plus`）。
- 状态标记与动作入口不复用同一形状：单点 `dot` 只当状态标记（连接中 / WebSocket），行尾「更多操作」入口一律用三点 `more`。
- **禁止**：引入图标库、使用 emoji 当图标、使用彩色/多色图标、用图片代替图标。

## 7 文案规范

- 全中文；专有名词（GET、JSON、cURL、SQLite、Cookie、Bearer、Basic、API Key、URL）保留原文。
- 按钮用动词或动宾短语：`发送`、`保存`、`新建集合`、`导入 cURL`、`清空历史`。不写「确定/OK」以外的英文。
- 对话框标题写对象不写动作：`保存请求`、`环境变量 · 当前：固定环境`。
- 应用内提示框的键盘约定要在 `field-hint` 里写明，例如批量粘贴：「Enter 换行，Ctrl+Enter 确定；空行会被忽略。」——单行输入才是 Enter 直接提交。
- 提示框要「带着当前数据打开」而不是从空白开始：批量粘贴预填表格现有行（禁用行以 `# ` 开头），确定后整体替换；数据完全没改时直接返回，不触发无意义的重绘与落盘。剪贴板内容与现有内容不同时，用 `.prompt-actions` 里的 `.link-btn`（如「用剪贴板内容替换」）让人一键切换来源。
- 带代码的输入框（脚本、请求体）必须走等宽字体 + 2 空格缩进，不做行号、不做语法主题以外的装饰；用户脚本是我们执行的代码，来自导入文件时必须先展示「信任并启用」再执行。
- 「取消」与「内容是空的」是两件事，必须分开处理：取消 = 什么都不做（`askText` 返回 `null`，调用方直接返回，不解析、不落盘、不弹错误提示）；把内容主动清空后确定 = 明确的清空意图（清空数据并提示「已清空 N 项」）。不得把取消当成一份空内容去校验，否则会误报「格式不对」。
- 错误提示 = 现象 + 下一步：`域名解析失败：请检查地址拼写或网络连接`，换行补一句「检查地址、端口、服务是否启动，以及系统代理是否拦截了该地址」。
- 空状态 = 说明 + 怎么做：`还没有响应 / 按 Ctrl+Enter 或点「发送」开始第一次请求。`
- 统一术语表（不得混用同义词）：

| 概念 | 唯一说法 | 不要写 |
| --- | --- | --- |
| 一次 HTTP 调用 | 请求 | 接口调用、API 调用 |
| 返回内容 | 响应 / 响应体 / 响应头 | 返回结果、response |
| 请求集合 | 集合 | 项目、分组、Collection |
| 集合内的分组 | 文件夹 | 目录、子集合 |
| 变量集合 | 环境 | 配置文件、Profile |
| 顶部打开的编辑器 | 标签页 | 窗口、Tab |
| 请求记录 | 历史 | 记录、日志 |

- 不用感叹号、不用「哦/啦/呢」、不写「请稍候…」这类空话（进度用真实状态文案）。

## 8 禁用清单（红线）

1. 新增第二种强调色，或把状态色（绿/橙/红/紫）当装饰色用。
2. 在组件里写裸色值 / 裸字号 / 裸圆角 / 裸阴影（`npm run lint:ui` 会拦）。
3. 引入 UI 组件库、CSS 框架、图标库、Web 字体。

## 10 变更流程（改令牌 = 三处同步 + 全库替换）

```text
1. 改本文件（先定语义与用途）
2. 改 src/style.css：:root / html[data-theme="dark"] / html[data-theme="auto"] 三块
3. 全库替换引用（grep 旧令牌名），跑 npm run lint:ui 确认无漏
4. npm run e2e 截图核对浅色与深色
5. 一个逻辑改动一个提交，提交信息写清「令牌变更 + 影响范围」
```

破坏性令牌变更（改名、删档位）等同接口变更：先在本文档标注替换关系，再一次性全库替换，不留新旧两套。
